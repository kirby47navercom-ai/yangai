# 대화 흐름 수정 및 검증 기록

검증일: 2026-09-24

## 결론

대화 기록과 제어 요청을 분리한 기반 위에 로컬 행동 판단과 대사 검토를 추가하였습니다. 사용자 기억과 직전 입장·감정을 참고하여 행동과 구체적인 소재를 선택하고, 대사를 생성한 뒤 여러 오류 항목을 독립적으로 판단합니다. 주기적으로 억지로 화제를 바꾸던 요청은 제거하였습니다.

이 구조는 Jev의 선택·판정 방식에서 착안한 로컬 구현입니다. 외부 Jev API, TypeSafe API 키, 유료 판단 서비스를 사용하지 않습니다. Jev의 전용 모델 구조를 재현한 것도 아닙니다. 같은 Gemma 모델을 단계별로 호출하며, 구조를 분리하였다는 사실만으로 자연스러운 자율 방송 품질이 완성되었다고 평가하지 않습니다.

## 확인한 원인

1. 과거 하나의 발언이 최근 대화, 시스템 영역의 최근 대화, 마지막 생각, 자동 요청에 중복 전달되었습니다. 모델이 자기 발언을 반복적으로 모방하기 쉬운 입력이었습니다.
2. 기존 프롬프트와 기억을 입력한 실측에서는 입력이 약 6,657토큰인 사례가 있었지만, 설정된 컨텍스트는 4,096이었습니다. 동일 요청에서 짧은 컨텍스트를 사용하면 실제 처리되는 입력이 줄었습니다. 설정을 8,192로 늘리고 중복 입력도 제거하였습니다.
3. 자동 독백이 쌓이면 사용자의 발언이 최근 기록에서 사라졌습니다. 저장되어 있다는 사실만으로 다음 생성 요청에 전달되는 것은 아니었습니다.
4. 화면이 유사하다고 판단되면 새로 읽은 내용 대신 과거 메모를 전달하는 경로가 있었습니다. 이전 관찰을 복사하라는 화면 모델 지시도 제거하였습니다.
5. 단순 문자열 검사에서는 짧아진 반복문을 놓치고, 반대로 같은 고유명사나 주제를 쓴 정상적인 후속 발언을 반복으로 판단하는 경우가 있었습니다.
6. 실패 시 준비된 대사를 순환시키는 경로는 실제 대화 발전을 만들지 못했습니다. 이 경로를 제거하였습니다.
7. 사용자 질문에 `게임`이나 `공부`가 포함되기만 해도 추가 화면 분석을 요청하였습니다. 취향이나 의견을 묻는 대화는 자동으로 화면 질문으로 분류하지 않도록 수정하였습니다.

## 변경된 대화 처리

- 실제 사용자 발화와 자동 진행 이벤트를 구분합니다. 제어 이벤트는 사용자 기억으로 저장하지 않습니다.
- 대사와 주제·입장·감정·다음 소재를 구조화하여 한 번에 생성합니다. 실제 대사만 UI와 음성 재생에 전달합니다.
- 최근 사용자 대화의 자리를 일부 확보하고, 사용자가 직접 말한 사실의 인용문을 별도 보관합니다. 인용문은 원문 포함 여부를 검사하며 자동 발언에서는 추가하지 않습니다.
- 별도 판단 요청이 최신 사용자 요구와 직전 대화의 연결점을 확인하고, 직접 답변·내용 발전·타협·가정·화면 반응·화제 전환 중 다음 행동을 고릅니다. 행동과 함께 아직 말하지 않은 구체적인 소재를 작성합니다. 사용자에게 기억을 확인해 주는 응답에는 억지로 새로운 소재를 요구하지 않습니다.
- 반복 후보는 근거와 함께 다시 생성하도록 요청합니다. 자동 발언 재생성 시에는 이미 끝난 대화를 참고 기록으로 다시 제시하는 경로도 사용합니다.
- 현재 의미 검사는 여덟 개의 독립된 참·거짓 항목을 사용합니다. 최신 사용자 요구 무시, 요청하지 않은 상상의 연속 확장, 이미 답한 정보 재질문, 미응답 질문 반복, 동의하지 않은 약속의 기정사실화, 근거 없는 실제 사건, 같은 결론의 재진술, 무관한 화제 전환을 검사합니다. 특정 어휘의 금지 목록이나 검증된 확률값이 아니며 오판할 수 있습니다.
- 초안이 거절되면 실패 사유와 초안을 참고하여 행동·소재 단계부터 다시 구성합니다. 폐기된 초안은 사용자에게 이미 말한 내용이나 장기 기억으로 기록하지 않습니다.
- 수락된 답변의 상태와 최근 대화는 매번 저장합니다. 과거 세션 원본은 삭제하지 않습니다.

캐릭터 프롬프트는 모델에 매번 전달되는 설정입니다. 모델을 재학습하거나 인간의 의식을 구현한 것이 아닙니다. 상태 필드의 존재가 그 자체로 올바른 판단을 의미하지는 않습니다.

## 실제 모델 시험

마이크, 실제 화면 캡처, TTS를 사용하지 않고 동일 PC의 로컬 Ollama를 호출하였습니다. 화면 입력은 고정된 시험용 관찰 문장이며, 사용자 발화도 시험용입니다. 실제 개인 대화는 공개하지 않습니다.

Qwen3 8B, Qwen3 4B, Qwen2.5 14B, Qwen3.5 9B, Gemma4 12B를 시험하였습니다. 프롬프트와 처리 방식이 중간에 변경되었으므로 이 결과를 일반적인 모델 순위나 엄밀한 성능 비교로 해석해서는 안 됩니다.

- Qwen3 8B: 수정 초기 10회 시험 중 3회에서 반복 재생성에 실패하였습니다.
- Qwen3 4B: 사용한 설정에서 내부 추론 형태의 영어 텍스트가 대사에 나타났습니다. 정상 응답으로 평가하지 않았습니다.
- Qwen2.5 14B: 답변은 생성되었으나 반복적인 조언·설명 위주의 말투가 남았습니다.
- Qwen3.5 9B: 직접 응답 모드에서도 한국어 및 역할 유지가 불안정하였습니다. 별도의 추론 모드 단일 시험에서는 약 30.9초 동안 2,048토큰을 사용하고도 최종 대사가 없었습니다.
- Gemma4 12B: 최종 설정의 16회 시험에서 빈 대사 및 재생성 실패는 없었습니다. 이름·주제·취향 회상이 가능하여 이번 설정의 기본 모델로 선택하였습니다. 의미상 반복과 부정확한 설명은 여전히 발생했습니다.

모델 정보는 [Ollama Gemma4 배포 정보](https://ollama.com/library/gemma4)와 [Qwen3.5 공식 모델 카드](https://huggingface.co/Qwen/Qwen3.5-9B)를 참고하였습니다. 다른 모델을 선택하려면 `config.json`의 `model`을 변경하고 같은 회귀 시험을 다시 수행해야 합니다.

### 이전 구조의 16회 시험에서 확인한 사항

시험에는 이름 지정, 공부와 게임의 구분, 무입력 자동 발언, 현재 주제 질문, 캐릭터 정체성 질문, 취향 충돌, 파일 저장 후 재로딩이 포함되었습니다.

- 사용자가 말하지 않는 구간에도 대사를 생성하였습니다.
- 화면에 있는 단어만 해설하지 않고, 네트워크에서 길거리 환경 등 다른 소재로 이동하였습니다.
- 게임 실험을 좋아한다는 캐릭터 취향과 승리를 선호하는 사용자 취향을 구분하였습니다.
- 마지막 회상 답변에서 `모래`, `TCP 연결`, 승리를 선호하는 게임 취향을 다시 언급하였습니다.
- 각 요청의 생성·검사 시간은 약 3.5~6.5초였습니다. 이미 모델을 사용한 상태의 수치이며, 음성 합성·재생, 실제 화면 분석, 콜드 로딩은 포함하지 않습니다.

다음 항목은 여전히 미해결입니다.

- 이미 물은 게임 취향을 비슷하게 다시 질문하는 경우가 있습니다.
- 같은 취향의 이유를 바꾸어 말하는 응답을 의미 검사도 통과시키는 경우가 있습니다.
- 화제 전환이 자연스러운 연상보다 요청에 따른 전환처럼 들리는 경우가 있습니다.
- 기술 설명에서 서로 다른 개념을 뭉뚱그리는 등 사실 오류가 발생할 수 있습니다.
- 긴 방송 전체의 일관성 및 실제 게임 화면과 함께 작동하는 상황은 이번 시험으로 검증하지 않았습니다.

### 분리된 로컬 판단의 고정 사례 시험

이번 구조에서는 실제 Gemma 모델에 시험용 대화와 후보 대사를 전달하여 10개 사례를 점검하였습니다. 정확한 오류 종류까지 일치한 사례는 9개였습니다. 거절해야 할 후보와 통과시켜야 할 후보의 구분은 10개에서 모두 일치하였지만, 이를 일반적인 정확도 수치로 해석해서는 안 됩니다.

- 이미 답한 게임 취향을 다시 묻는 질문, 말만 바꾼 취향 반복, 무관한 화제 전환, 보지 않은 승리 장면을 거절하였습니다.
- 새로운 타협안, 조건부 가정, 아직 알려주지 않은 정보를 묻는 후속 질문을 통과시켰습니다.
- 이름과 공부 주제를 답하는 정상적인 회상 문장을 중복 질문으로 막지 않았습니다.
- 사용자 동의 없이 성립했다고 말한 약속은 거절했으나, 구체적인 사유를 근거 없는 동의가 아니라 반복으로 분류하였습니다. 이 세부 분류 오류는 남아 있으며 회귀 스크립트도 실패로 보고합니다.
- 동의를 조건으로 한 제안은 실제로 합의했다는 주장과 구별하였습니다.

개발 도중에는 정상적인 회상 답변을 중복 질문으로 거절한 실패도 발생했습니다. 검사 항목을 후보 대사 기준으로 명시하도록 수정하고 해당 문장을 고정 회귀 사례에 추가했습니다. 초기의 성공 사례만으로 전체 문제가 해결되었다고 간주하지 않습니다.

### 분리된 판단을 적용한 16회 연속 시험

최종 실행에서는 16회 모두 대사를 반환하였고, 저장 후 다시 읽은 마지막 답변에서 시험용 이름 `모래`, 공부 주제 `TCP`, 실험보다 승리를 선호한다는 취향을 회상하였습니다. 음성·실제 화면 캡처·콜드 로딩을 제외한 판단·생성·검사 시간은 약 8.1~13.4초였습니다. 예전의 3.5~6.5초 수치를 새 구조의 응답 시간으로 사용해서는 안 됩니다.

단어 하나만 반복하는 대신 신령의 과거와 디지털 방송, 게임에서 생길 법한 가정으로 발언이 이어졌습니다. 그러나 다음 품질 문제는 남아 있습니다.

- 질문을 연속으로 던지거나 비슷한 가정을 조금씩 확대하는 대사가 여전히 나옵니다.
- 사용자가 실험을 싫어한다고 말해도, 자신의 실험 취향을 충분히 조정하지 않고 장난스럽게 넘기는 경우가 있습니다.
- `stance` 상태 메모에서 자기 제안을 이미 합의한 내용처럼 요약하는 사례가 있었습니다. 상태는 주관적 자료로 구분하지만 모델이 이후 이를 잘못 해석할 가능성은 남아 있습니다.
- TCP 비유에서 연결 수립, 중복 처리, 데이터 무결성 등의 역할을 혼동하는 설명이 나왔습니다. 이번 검사는 외부 지식의 정확성을 보증하는 사실 검증기가 아닙니다.

따라서 대사가 생성되었다는 검사 결과와 자연스러운 방송 품질의 통과 여부는 별개입니다. 긴 실방송·시청자 여러 명·실제 게임 화면과 음성을 함께 사용하는 시험은 수행하지 않았습니다.

## 입력 경로 추가 검증 — 2026-09-26

사용자가 제공한 방송 로그에서는 상상한 보물·요괴·왕관에 새로운 설정만 계속 붙였습니다. 실제 실행 기록에서도 확인 가능한 판단 중 20건이 `hypothetical`로 분류되었습니다. 대사마다 세부 소재가 달라졌다는 이유만으로 방송 흐름이 발전한 것으로 취급한 것이 문제였습니다.

다음 입력 처리 문제를 확인하고 수정하였습니다.

- 기존 마이크 루프는 TTS 작업 중 녹음을 건너뛰었습니다. 긴 음성이 이어지면 사용자 발화를 받을 기회가 적었습니다. 이제 연속 입력 스트림과 STT 대기 버퍼를 사용하며 헤드폰 모드에서는 TTS 중에도 인식합니다.
- 사용자 발화 감지 시 기존 음성의 재생 및 대기 문장을 취소합니다. 자동 대사 스트림도 다음 토큰 또는 단계 경계에서 취소하여 사용자 입력을 우선합니다. 진행 중인 비스트리밍 모델 요청과 음성 합성 HTTP 요청은 즉시 종료되지 않으므로 지연이 완전히 제거된 것은 아닙니다.
- 화면 관찰 콜백이 TTS 또는 대화 처리 중 들어오면 반응 요청을 버렸습니다. 이제 미처리 관찰을 보존하고 다음 자동 차례에 전달합니다. 첫 관찰 전에는 화면을 이미 본 것처럼 자동 발언을 시작하지 않습니다.
- 화면 관찰 유효 시간은 실제 캡처 시각부터 계산합니다. 오래된 이미지가 느린 분석 직후 새 이미지로 취급되지 않도록 하였습니다.

## 반복 독백과 화면 질문 추가 수정 — 2026-09-26
