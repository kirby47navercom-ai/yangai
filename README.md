# 하나(Hana) 로컬 버튜버

하나는 Windows 환경에서 실행되는 로컬 버튜버 애플리케이션입니다. 사용자의 음성을 마이크로 인식하고, 선택한 화면 또는 전체 화면을 관찰하며, 대화 흐름과 장기 기억을 참고하여 캐릭터성을 유지한 방송 멘트를 생성합니다.

하나의 캐릭터는 대한민국의 언어·문화·계절·사람들의 기억에서 태어난 가상의 신령이자 게임 버튜버입니다. 하나는 정해진 답변 목록을 선택하는 방식이 아니라, 현재 대화와 화면 관찰 내용을 로컬 LLM으로 해석하여 매번 새로운 답변을 생성합니다.

> 하나는 대한민국 정부나 공공기관의 공식 대변인이 아닙니다. 캐릭터 설정에 기반한 가상의 방송 인격입니다.

## 주요 기능

| 기능 | 설명 |
| --- | --- |
| 로컬 대화 생성 | Ollama의 `gemma4:12b` 모델을 사용합니다. 캐릭터 설정, 대화 이력, 사용자 발언과 방송 상태를 입력으로 전달합니다. 모델은 `config.json`에서 변경할 수 있습니다. |
| 분리된 로컬 판단 | 대사 생성 전에 다음 행동과 구체적인 소재를 정하고, 생성 후에는 독립된 참·거짓 항목으로 대화 오류를 검사합니다. 외부 Jev API나 API 키를 사용하지 않습니다. |
| 자동 Ollama 관리 | 하나를 실행할 때 로컬 Ollama 서버가 꺼져 있으면 `ollama serve`를 자동으로 시작합니다. 하나가 직접 시작한 프로세스만 종료 시 정리합니다. |
| 마이크 대화 | `faster-whisper`로 사용자의 음성을 인식합니다. 별도의 채팅 입력 없이도 방송 중 음성 대화를 진행할 수 있습니다. |
| 화면 관찰 | `qwen2.5vl:3b`로 전체 화면 또는 사용자가 선택한 창을 주기적으로 분석합니다. |
| 선제적 방송 | 사용자의 입력을 기다리지 않고 화면의 변화, 게임 상황, 방송 분위기를 바탕으로 하나가 먼저 말할 수 있습니다. |
| GPT-SoVITS 음성 | `v2ProPlus`의 GPT-SoVITS 서버를 사용합니다. 답변 생성 및 검사가 끝나면 실제 대사만 문장 단위로 합성·재생합니다. |
| Piper 음성 대체 | GPT-SoVITS를 사용할 수 없을 때 로컬 Piper 음성으로 대체할 수 있습니다. |
| 장기 기억 | 방송 세션, 사용자 정보, 관계, 감정, 진행 중인 주제와 화면 흐름을 저장하여 다음 실행에도 이어갑니다. |
| 캐릭터 프롬프트 | 하나의 정체, 역사, 외형, 게임 취향, 방송 태도, 감정 표현, 말투를 `hana_prompt.txt`에서 관리합니다. |

## 동작 구조

하나는 다음 구성 요소를 함께 사용합니다.

1. **대화 모델**: Ollama의 `gemma4:12b`
2. **화면 모델**: Ollama의 `qwen2.5vl:3b`
3. **음성 인식**: `faster-whisper`의 `small` 모델
4. **기본 음성 합성**: GPT-SoVITS v2ProPlus
5. **대체 음성 합성**: Piper 한국어 음성
6. **GUI**: Python Tkinter
7. **기억 저장소**: JSON 및 JSONL 파일

대화 모델에는 다음 정보가 함께 전달됩니다.

- `hana_prompt.txt`에 정의된 하나의 캐릭터 설정
- 현재 방송 세션의 최근 대화
- 이전 세션에서 저장된 장기 기억
- 하나의 감정 상태와 사용자와의 관계 상태
- 최근 화면 관찰과 직전 화면에서 이어진 흐름
- 현재 사용자의 음성 또는 텍스트 입력

화면은 대화의 참고 자료이며 발언 주제를 강제로 지정하지 않습니다. 모델은 대사와 함께 현재 주제, 자신의 입장, 감정, 다음에 이어갈 거리를 생성합니다. 이 상태는 다음 발언과 다음 실행에 전달됩니다. 다만 상태 필드가 존재한다는 것만으로 자연스러운 대화나 사람과 같은 사고가 보장되지는 않습니다.

### 판단과 대사 생성의 분리

Jev의 구조화된 선택·판정 방식에서 착안하여 다음 처리를 로컬로 구현하였습니다. TypeSafe의 Jev 서비스, 모델 가중치 또는 전용 추론 구조를 사용하거나 복제한 것은 아닙니다. 같은 Gemma 모델에 역할과 출력 형식이 다른 요청을 순서대로 보내므로, 전용 판단 모델과 같은 정확도·속도를 보장하지 않습니다.

1. **상태 입력**: 실제 사용자 발언, 최근 대화, 사용자 기억, 직전 입장·감정·다음 소재와 최신 화면 관찰을 구분하여 전달합니다. 자동 진행 이벤트는 실제 사용자 발언에서 제외합니다.
2. **로컬 판단**: 현재 사용자 요구를 확인한 뒤 `respond`, `develop`, `reconcile`, `hypothetical`, `screen`, `transition` 중 다음 행동을 선택합니다. 각각 직접 답변, 내용 발전, 의견 차이 조율, 가정, 화면 반응, 연결된 화제 전환을 의미합니다. 이어갈 구체적인 소재도 작성하며 준비된 대사를 고르지 않습니다.
3. **대사 생성**: 선택한 행동과 소재를 참고하여 하나의 캐릭터 설정에 맞는 대사를 생성합니다. 사용자가 새로 말하면 그 발언을 우선합니다.
4. **로컬 검토**: 이미 알려준 정보를 다시 묻는지, 실제 사건·사용자 동의를 꾸며내는지, 같은 결론을 바꾸어 말하는지, 화제가 근거 없이 튀는지를 독립된 참·거짓 항목으로 검사합니다. 이 값은 모델의 판정이며 검증된 확률값이 아닙니다.
5. **출력과 저장**: 검사를 통과한 `speech`만 채팅과 음성에 전달하고 방송 상태를 저장합니다. 내부 판단이나 자동 진행 지시문은 대사로 출력하지 않습니다.

반복 또는 오류가 감지되면 폐기된 초안과 수정 사유를 참고하여 소재부터 다시 구성합니다. 특정 단어나 주제를 금지하거나, 실패 시 준비된 멘트를 대신 읽는 방식은 사용하지 않습니다. 세 번 모두 실패하면 상태 영역에 오류를 표시합니다. 호출·형식 오류도 정상 대사로 숨기지 않습니다.

기본 설정에서는 판단과 생성 요청이 로컬 Ollama로만 전달되며 별도의 API 이용료가 없습니다. 하드웨어·전력 비용은 발생하고, 모델이나 라이브러리의 최초 다운로드에는 인터넷이 필요할 수 있습니다. `ollama_url`을 원격 주소로 바꾸면 해당 서버로 입력이 전송됩니다.

## 시스템 요구 사항

- Windows 10 또는 Windows 11
- Python 설치 환경
- Ollama 설치
- 대화 모델 `gemma4:12b`
- 화면 모델 `qwen2.5vl:3b`
- 마이크 사용 시 정상적으로 연결된 입력 장치
- GPT-SoVITS 음성 사용 시 `v2ProPlus` 설치 환경과 참조 음성 파일

현재 설정은 다음 경로를 기준으로 작성되어 있습니다.

```text
%USERPROFILE%\OneDrive\바탕 화면\v2ProPlus
```

GPT-SoVITS 설치 위치가 다른 경우에는 `config.json`의 `gpt_sovits_*` 항목을 수정해야 합니다.

## 최초 설치

### 1. Ollama 설치

Ollama가 설치되어 있지 않은 경우 먼저 Windows용 Ollama를 설치해야 합니다. 현재 PC에서는 다음 실행 파일을 사용합니다.

```text
%LOCALAPPDATA%\Programs\Ollama\ollama.exe
```

하나를 실행할 때 Ollama 서버가 꺼져 있어도 하나가 자동으로 서버를 시작하지만, Ollama 프로그램 자체가 설치되어 있지 않으면 자동으로 설치할 수 없습니다.

### 2. 기본 환경 설치

프로젝트 폴더에서 `setup_hana.bat`을 한 번 실행합니다.

설치 스크립트는 다음 작업을 수행합니다.

- Python 가상 환경 `.venv` 생성
- Piper, 화면 캡처, 마이크, 음성 인식, PyInstaller 패키지 설치
- 한국어 Piper 음성 모델 다운로드
- Piper가 사용할 `espeak-ng-data` 복사
- `gemma4:12b` 대화 모델 확인 및 다운로드
- `qwen2.5vl:3b` 화면 모델 확인 및 다운로드

GPT-SoVITS는 별도의 `v2ProPlus` 환경을 사용하므로 `setup_hana.bat`이 GPT-SoVITS 자체를 설치하지는 않습니다.

### 3. 실행

설치 후에는 다음 파일을 실행합니다.

```text
start_hana.bat
```

실행 순서는 다음과 같습니다.

1. `start_hana.bat`이 숨김 실행기인 `start_hana.vbs`를 호출합니다.
2. `dist\Hana\Hana.exe`가 있으면 빌드된 GUI를 실행합니다.
3. EXE가 없으면 `run_hana.ps1`을 통해 Python GUI를 실행합니다.
4. 하나가 로컬 Ollama API 연결을 확인합니다.
5. Ollama가 꺼져 있으면 `ollama serve`를 숨김으로 실행합니다.
6. Ollama API가 준비된 뒤 마이크, 화면 관찰, 음성 기능을 시작합니다.

## Ollama 자동 실행 및 종료

하나는 `http://127.0.0.1:11434`의 Ollama API를 확인합니다.

### 시작 시 동작

- Ollama API가 이미 실행 중이면 기존 서버를 그대로 사용합니다.
- API가 응답하지 않으면 시스템에서 `ollama.exe`를 찾습니다.
- `ollama serve`를 별도 콘솔 창 없이 실행합니다.
- 최대 45초 동안 `/api/tags` 응답을 확인합니다.
- API가 준비되면 하나의 방송을 시작합니다.

### 종료 시 동작

- 하나가 직접 시작한 Ollama 프로세스만 종료합니다.
- 하나를 실행하기 전에 이미 실행 중이던 Ollama는 종료하지 않습니다.
- Ollama 실행 파일을 찾지 못하거나 45초 안에 서버가 준비되지 않으면 GUI 상태 영역에 원인을 표시합니다.

첫 방송에서 모델이 GPU 메모리에 올라가는 시간은 Ollama 서버 시작 시간과 별개입니다. 서버가 자동으로 시작되어도 첫 답변은 모델 로딩으로 늦어질 수 있으며, 이후 응답은 일반적으로 더 빨라집니다.

## GUI 사용법

GUI에는 다음 기능이 있습니다.

### 마이크

마이크 기능이 켜져 있으면 하나가 계속 사용자의 음성을 감지합니다. 음성이 끝난 것으로 판단되면 `faster-whisper`가 음성을 텍스트로 변환하고, 변환된 문장을 대화 모델에 전달합니다.

하나가 음성을 재생하는 동안에는 자기 음성을 마이크로 다시 인식하지 않도록 마이크 입력을 잠시 중지합니다.

### 화면 관찰

화면 관찰 설정에서 다음 중 하나를 선택할 수 있습니다.

- 전체 화면
- 열려 있는 특정 창

선택한 창이 종료되면 화면이 검은색으로 고정되지 않습니다. 하나는 선택한 창을 찾을 수 없는 경우 전체 화면 또는 현재 데스크톱 영역을 대체 화면으로 사용합니다.

화면 관찰은 기본적으로 분석을 마친 뒤 5초를 기다리고 다시 수행합니다. 화면 분석 요청의 제한 시간은 기본 30초입니다. 따라서 실제 관찰 주기는 분석 시간에 따라 더 길어질 수 있습니다.

화면 분석 중 사용자의 음성이나 자동 대화 요청이 들어오면 새 화면 분석을 시작하지 않고 대화 처리를 우선합니다.

### 음성

현재 `config.json`은 GPT-SoVITS를 기본 음성 엔진으로 사용하도록 설정되어 있습니다.

GPT-SoVITS 음성은 다음 순서로 처리됩니다.

1. 모델의 답변 생성과 구조·반복 검사가 끝날 때까지 기다립니다.
2. 검사를 통과한 대사를 문장 단위로 분리하여 GPT-SoVITS 서버에 보냅니다.
3. WAV 파일이 생성되면 Windows 기본 오디오 장치로 재생합니다.
4. 다음 문장은 앞 문장의 재생이 끝난 뒤 순서대로 재생합니다.

현재 구현은 첫 토큰부터 즉시 음성을 내는 방식이 아닙니다. 대화 생성·검사·음성 합성·재생 대기 시간이 합산됩니다. 음성 엔진과 참조 음성 설정은 이번 대화 흐름 수정에서 변경하지 않았습니다.

GPT-SoVITS를 사용할 수 없을 때에는 `config.json`에서 다음과 같이 Piper로 전환할 수 있습니다.

```json
{
  "tts_engine": "piper"
}
```

### 자동 방송 멘트

하나는 사용자의 입력이 없어도 자동 발언을 요청합니다. 화면 관찰이 실패하거나 비활성화되어 있어도 이전 대화와 캐릭터의 관심사를 바탕으로 이어갈 수 있습니다. 화면이 없을 때에는 현재 화면을 본 것처럼 말하지 않도록 지시합니다.

하나의 답변과 음성 재생이 끝난 뒤 기본적으로 3초를 기다리고 다음 생성 요청을 시작합니다. 3초 안에 다음 음성이 재생된다는 뜻은 아닙니다. 자동 발언 생성 도중 사용자가 말하면, 완료된 자동 발언을 내보내지 않고 대기 중인 사용자 발화에 대응합니다.

## 캐릭터 설정

캐릭터의 핵심 설정은 다음 파일에서 관리합니다.

```text
hana_prompt.txt
```

현재 하나는 다음과 같은 설정을 사용합니다.

- 대한민국의 언어, 문화, 계절, 사람들의 기억에서 태어난 가상의 신령
- 인간이 아니라 인간 세상에 머물기 위해 인간의 모습과 목소리를 선택한 존재
- 게임과 방송을 좋아하는 버튜버
- 화면에 보이는 사실과 자신의 감정·판단을 구분하는 방송인
- 사용자와 시청자를 고객이나 상사가 아닌 방송 동료로 대하는 관계
- 장난스럽고 살짝 도도하지만 가까운 사람에게는 다정한 성격
- 정해진 답변 목록 대신 대화 모델로 대사를 생성하는 가상의 방송 인격

캐릭터의 말투, 과거, 감정, 게임 취향, 방송 행동을 수정하려면 `hana_prompt.txt`를 수정합니다. 이는 매 요청에 전달하는 설정이며, 모델의 가중치를 재학습한 것은 아닙니다. EXE로 실행하는 경우에는 `dist\Hana\hana_prompt.txt`가 사용됩니다.

## 기억과 세션 저장

하나의 기억은 프로그램 실행 위치의 `data` 폴더에 저장됩니다. EXE로 실행하는 경우 기본 위치는 다음과 같습니다.

```text
dist\Hana\data
```

### 방송 세션

방송을 시작할 때마다 다음 형식의 새 파일이 생성됩니다.

```text
data\sessions\session_YYYYMMDD_HHMMSS_프로세스번호.jsonl
```

현재 방송 세션의 사용자 발화와 하나의 답변은 이 파일에 순서대로 저장됩니다.

### 장기 기억

장기 기억은 다음 파일에 저장됩니다.

```text
data\memory.json
```

기억에는 다음 정보가 포함될 수 있습니다.

- 사용자가 직접 말한 사실과 선호
- 사용자와 하나의 관계 상태
- 하나의 현재 감정
- 이어지고 있는 주제
- 최근 대화 일부
- 마지막으로 관찰한 화면 흐름
- 이전 방송에서 생성된 요약
- `broadcast_state`: 현재 화제, 입장, 감정, 다음에 이어갈 거리
- `user_quotes`: 사용자가 실제로 말한 호칭·선호·사실의 인용문

수락된 답변마다 현재 상태와 최근 대화를 저장하며, 사용자 발화가 8회 누적될 때마다 별도의 기억 요약을 요청합니다. 사용자 인용문은 모델이 골라도 현재 사용자 발화에 실제로 포함된 문자열만 저장합니다. 자동 발언이 사용자 사실로 등록되는 것을 막기 위한 구분입니다. 인용문은 최근 30개까지 유지하며 완전한 영구 회상을 보장하지 않습니다.

자동 발언이 많이 쌓여도 최근 사용자 대화가 기록 창에서 즉시 밀려나지 않도록 일부 자리를 확보합니다. 과거 버전의 출처 없는 자동 독백은 반복 오염을 줄이기 위해 다음 프롬프트에서 제외하지만 원본 세션 파일은 삭제하지 않습니다. 이전 화면 메모는 재실행 직후의 실제 화면으로 취급하지 않습니다.

기억 파일의 저장과 모델의 정확한 회상은 별개입니다. 저장된 정보를 모델이 잘못 해석하거나 놓칠 수 있으며, 오래된 요약에도 오류가 있을 수 있습니다. 생성 후보와 재생성 사유는 로컬 `data\generation.jsonl`에 기록합니다. 이 파일과 세션 기록에는 대화 내용이 포함될 수 있으므로 공개 저장소에 올리지 않도록 제외되어 있습니다.

## 주요 설정

주요 설정은 `config.json`에서 변경할 수 있습니다.

| 항목 | 기본값 | 설명 |
| --- | --- | --- |
| `model` | `gemma4:12b` | 대화와 캐릭터 답변을 생성하는 모델입니다. Ollama JSON 구조 출력을 지원해야 합니다. |
| `vision_model` | `qwen2.5vl:3b` | 화면과 이미지 내용을 분석하는 모델입니다. |
| `ollama_url` | `http://127.0.0.1:11434` | Ollama API 주소입니다. 로컬 자동 시작은 로컬 주소에서만 동작합니다. |
| `num_ctx` | `8192` | 캐릭터 설정과 대화·상태를 전달하는 컨텍스트 크기입니다. |
| `num_predict` | `384` | 기존 답변 예산입니다. 구조화된 상태를 위한 256토큰을 더하여 총 640토큰을 요청합니다. 필드별 사용량은 모델에 따라 달라집니다. |

| `semantic_repeat_check` | `true` | 기록이 있는 대사에서 반복·중복 질문·근거 없는 사건·화제 이탈을 별도 모델 요청으로 검사합니다. 추가 지연이 발생하며 오판할 수 있습니다. |
| `recent_messages` | `16` | 현재 답변에 직접 전달할 최근 대화 수입니다. |
| `screen_interval` | `5` | 화면 관찰 간격입니다. 초 단위입니다. |
| `vision_response_timeout` | `30` | 화면 분석 요청의 최대 대기 시간입니다. |
| `screen_capture_mode` | `screen` | `screen`은 전체 화면, `window`는 선택한 창을 사용합니다. |
| `tts_engine` | `gpt_sovits` | `gpt_sovits` 또는 `piper`를 사용할 수 있습니다. |
| `tts_enabled` | `true` | 음성 출력을 켜거나 끕니다. |
| `talk_after_speech_seconds` | `3` | 하나의 음성 재생 후 다음 자동 멘트까지의 대기 시간입니다. |
| `idle_talk_enabled` | `true` | 사용자가 입력하지 않아도 하나가 먼저 말할 수 있도록 합니다. |
| `auto_memory` | `true` | 대화와 방송 흐름을 자동으로 기억합니다. |

설정 파일을 수정한 뒤에는 하나를 완전히 종료하고 다시 실행해야 변경 사항이 적용됩니다.

## 빌드

소스 코드에서 EXE를 다시 만들려면 프로젝트 폴더에서 다음 명령을 실행합니다.

```powershell
.\build_hana.ps1
```

빌드 결과는 다음 위치에 생성됩니다.

```text
dist\Hana\Hana.exe
```

빌드 스크립트는 임시 빌드 폴더를 사용하며, 기존 `dist\Hana\data` 폴더는 백업한 뒤 새 빌드 결과에 복원합니다. 따라서 세션 기록과 장기 기억은 빌드 과정에서 유지됩니다.

## 프로젝트 구조

```text
yangai/
├─ hana_app.py              # Tkinter GUI와 마이크·화면·대화 루프
```

## 문제 해결

### “Ollama 자동 시작 실패”가 표시되는 경우

다음 항목을 순서대로 확인합니다.

1. Ollama가 설치되어 있는지 확인합니다.
2. `%LOCALAPPDATA%\Programs\Ollama\ollama.exe`가 존재하는지 확인합니다.
3. `config.json`의 `ollama_url`이 `http://127.0.0.1:11434`인지 확인합니다.
4. `setup_hana.bat`을 실행하여 필요한 모델이 설치되어 있는지 확인합니다.
5. 다른 프로그램이 11434 포트를 사용하고 있지 않은지 확인합니다.

### 모델이 없다는 오류가 표시되는 경우

다음 명령으로 설치된 모델을 확인합니다.

```powershell
ollama list
```

필요한 모델이 없다면 `setup_hana.bat`을 다시 실행하거나 다음 명령을 직접 실행합니다.

```powershell
ollama pull gemma4:12b
ollama pull qwen2.5vl:3b
```

### 음성이 나오지 않는 경우

- `config.json`에서 `tts_enabled`가 `true`인지 확인합니다.
- GPT-SoVITS 경로와 참조 음성 파일 경로가 실제로 존재하는지 확인합니다.
- GPT-SoVITS를 사용할 수 없다면 `tts_engine`을 `piper`로 변경합니다.
- `data\tts_playback.log`와 `data\gpt_sovits.log`에서 음성 생성 및 재생 오류를 확인합니다.

### 화면을 제대로 읽지 못하는 경우

- 화면 관찰이 켜져 있는지 확인합니다.
- `qwen2.5vl:3b` 모델이 설치되어 있는지 확인합니다.
- 전체 화면 모드와 특정 창 모드를 바꾸어 확인합니다.
- 화면 모델은 작은 글자나 복잡한 화면을 항상 정확하게 읽지는 못합니다.
- 화면 분석 요청의 제한 시간은 기본 30초입니다. 최신 관찰이 45초 이상 갱신되지 않으면 현재 화면 자료에서 제외합니다.

## 제한 사항

- 하나는 화면 밖의 정보를 직접 볼 수 없습니다. 사용자가 말했거나 실제 화면에서 확인된 내용만 근거로 사용합니다.
- 첫 실행이나 모델이 메모리에서 내려간 직후에는 모델 로딩으로 응답이 늦어질 수 있습니다.
- 화면 분석과 음성 합성은 사용하는 GPU, CPU, 메모리, 디스크 속도에 따라 처리 시간이 달라집니다.
- GPT-SoVITS 참조 음성의 품질과 참조 문장에 따라 하나의 음성 품질과 감정 표현이 달라질 수 있습니다.
- 기억 파일을 삭제하거나 `memory.json`을 직접 수정하면 하나의 장기 기억과 관계 흐름이 변경됩니다.
- 로컬 모델의 한국어 표현, 사실 정확도, 자발적인 화제 전개에는 한계가 있습니다. 반복 검사도 의미상 같은 발언을 놓칠 수 있습니다.
- `emotion`은 캐릭터 반응을 이어가기 위한 상태 값입니다. 실제 감정이나 의식이 존재한다는 의미는 아닙니다.
- 응답 시간은 1초 이내로 보장하지 않습니다. 화면 모델 및 음성 모델과 GPU 메모리를 공유하면 추가 지연이 발생할 수 있습니다.

## 검증

마이크·화면 캡처·음성 출력을 실행하지 않고 대화 처리 회귀 검사를 수행할 수 있습니다.

```powershell
.\.venv\Scripts\python.exe test_hana.py
.\.venv\Scripts\python.exe test_dialogue_quality.py --live
.\.venv\Scripts\python.exe test_hana.py --live gemma4:12b --output data/diagnostics/conversation.json
```

첫 번째 명령은 구조 출력 분리, 행동 판단, 반복 재생성, 사용자 기억 유지 및 화면 메모 갱신을 검사합니다. 두 번째 명령은 실제 모델로 고정된 판단 사례와 네 차례의 자동 발언을 검사합니다. 세 번째 명령은 실제 모델과 16차례 대화하고 결과를 로컬 파일에 기록합니다. 실제 모델 시험은 시험용 대화와 빈 초기 기억을 사용하며 개인 기억 파일을 읽어 사용하지 않습니다. 이 시험은 실제 마이크나 게임 화면을 포함한 방송 전체 품질을 보증하지 않습니다.

수정 근거와 해결되지 않은 항목은 [대화 검증 기록](docs/conversation-validation.md)에 정리되어 있습니다.
