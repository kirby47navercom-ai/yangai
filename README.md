# 하나(Hana) 로컬 버튜버

하나는 Windows 환경에서 실행되는 로컬 버튜버 애플리케이션입니다. 사용자의 음성을 마이크로 인식하고, 선택한 화면 또는 전체 화면을 관찰하며, 대화 흐름과 장기 기억을 참고하여 캐릭터성을 유지한 방송 멘트를 생성합니다.

하나의 캐릭터는 대한민국의 언어·문화·계절·사람들의 기억에서 태어난 가상의 신령이자 게임 버튜버입니다. 하나는 정해진 답변 목록을 선택하는 방식이 아니라, 현재 대화와 화면 관찰 내용을 로컬 LLM으로 해석하여 매번 새로운 답변을 생성합니다.

현재는 개발 중인 구성입니다. 입력·기억 처리 검사와 실제 모델 시험을 구분하여 관리하며, 자동 독백의 의미상 반복·부자연스러운 화제 전환·재생성 실패가 남아 있습니다. 자연스러운 장시간 자율 방송이 완성된 상태가 아닙니다. 확인한 결과와 실패 사례는 [대화 검증 기록](docs/conversation-validation.md)에 공개합니다.

> 하나는 대한민국 정부나 공공기관의 공식 대변인이 아닙니다. 캐릭터 설정에 기반한 가상의 방송 인격입니다.

## 주요 기능

| 기능 | 설명 |
| --- | --- |
| 로컬 대화 생성 | Ollama의 `gemma4:12b` 모델을 사용합니다. 캐릭터 설정, 대화 이력, 사용자 발언과 방송 상태를 입력으로 전달합니다. 모델은 `config.json`에서 변경할 수 있습니다. |
| 분리된 로컬 판단 | 대사 생성 전에 다음 행동과 구체적인 소재를 정하고, 생성 후에는 독립된 참·거짓 항목으로 대화 오류를 검사합니다. 외부 Jev API나 API 키를 사용하지 않습니다. |
| 자동 Ollama 관리 | 하나를 실행할 때 로컬 Ollama 서버가 꺼져 있으면 `ollama serve`를 자동으로 시작합니다. 하나가 직접 시작한 프로세스만 종료 시 정리합니다. |
| 마이크 대화 | `faster-whisper`로 사용자의 음성을 인식합니다. 별도의 채팅 입력 없이도 방송 중 음성 대화를 진행할 수 있습니다. |
| 화면 관찰 | `qwen2.5vl:3b`로 전체 화면 또는 사용자가 선택한 창을 주기적으로 분석합니다. |
| 선제적 방송 | 사용자의 입력을 기다리지 않고 화면의 변화, 게임 상황, 방송 분위기를 바탕으로 하나가 먼저 말할 수 있습니다. |
| GPT-SoVITS 음성 | `v2ProPlus`의 GPT-SoVITS 서버를 사용합니다. 검사를 통과한 한 답변을 하나의 WAV로 합성·재생하며, 대사별 말투와 근접 좌우 위치를 적용합니다. |
| Piper 음성 대체 | GPT-SoVITS를 사용할 수 없을 때 로컬 Piper 음성으로 대체할 수 있습니다. |
| 장기 기억 | 방송 세션, 사용자 정보, 관계, 감정, 진행 중인 주제와 화면 흐름을 저장하여 다음 실행에도 이어갑니다. |
| 캐릭터 프롬프트 | 하나의 정체, 역사, 외형, 게임 취향, 방송 태도, 감정 표현, 말투를 `hana_prompt.txt`에서 관리합니다. |

## 동작 구조

하나는 다음 구성 요소를 함께 사용합니다.

1. **대화 모델**: Ollama의 `gemma4:12b`
2. **화면 모델**: Ollama의 `qwen2.5vl:3b`
3. **음성 인식**: `faster-whisper`의 `small` 모델
4. **기본 음성 합성**: GPT-SoVITS v2ProPlus
5. **대체 음성 합성**: Piper 한국어 음성
6. **GUI**: Python Tkinter
7. **기억 저장소**: JSON 및 JSONL 파일

대화 모델에는 다음 정보가 함께 전달됩니다.

- `hana_prompt.txt`에 정의된 하나의 캐릭터 설정
- 현재 방송 세션의 최근 대화
- 이전 세션에서 저장된 장기 기억
- 하나의 감정 상태와 사용자와의 관계 상태
- 최근 화면 관찰과 직전 화면에서 이어진 흐름
- 현재 사용자의 음성 또는 텍스트 입력

화면은 대화의 참고 자료입니다. 미처리된 새 관찰은 다음 자동 차례의 우선 근거가 되며, 같은 화면의 제목을 매번 다시 읽도록 요구하지 않습니다. 모델은 대사와 함께 현재 주제, 자신의 입장, 감정, 다음에 이어갈 거리와 생각의 완료 상태를 생성합니다. 이 상태는 다음 발언과 다음 실행에 전달됩니다. 다만 상태 필드가 존재한다는 것만으로 자연스러운 대화나 사람과 같은 사고가 보장되지는 않습니다.

### 판단과 대사 생성의 분리

Jev의 구조화된 선택·판정 방식에서 착안하여 다음 처리를 로컬로 구현하였습니다. TypeSafe의 Jev 서비스, 모델 가중치 또는 전용 추론 구조를 사용하거나 복제한 것은 아닙니다. 같은 Gemma 모델에 역할과 출력 형식이 다른 요청을 순서대로 보내므로, 전용 판단 모델과 같은 정확도·속도를 보장하지 않습니다.

1. **상태 입력**: 실제 사용자 발언, 최근 대화, 사용자 기억, 직전 입장·감정·다음 소재와 최신 화면 관찰을 구분하여 전달합니다. 자동 진행 이벤트는 실제 사용자 발언에서 제외합니다. 자동 생성에는 최근 여덟 발언을 시간순으로 전달하며, 화면 변경이나 생각 완료를 이유로 직전 발언을 제거하지 않습니다. 이 범위에서 빠진 사용자 원문과 이미 말한 내용은 별도 참고 자료로 전달합니다. 전체 최근 기록은 검토와 사용자 회상 응답에 계속 사용합니다. 원본 기록을 삭제하는 처리가 아닙니다.
2. **로컬 판단**: 현재 사용자 요구와 발언 근거를 확인한 뒤 직접 답변(`respond`), 내용 발전(`develop`), 의견 차이 조율(`reconcile`), 가정(`hypothetical`), 화면 반응(`screen`), 연결된 화제 전환(`transition`), 생각 마무리(`conclude`) 중 다음 행동을 선택합니다. 입력이 없는 상태에서 직전 가정을 바로 다른 가정으로 확장하는 선택은 제한하며, 이미 다룬 동일 화면을 매번 처음 발견한 것처럼 소개하지 않도록 합니다. 준비된 대사를 고르는 방식은 아닙니다.
3. **대사 생성**: 선택한 행동과 소재를 참고하여 하나의 캐릭터 설정에 맞는 대사를 생성합니다. 최근 대화는 사용자·하나의 실제 발언 역할을 유지하여 전달하고, 내부 진행 메모와 구분합니다. 사용자가 새로 말하면 그 발언을 우선합니다. 이미 처리한 화면 관찰은 사실 확인용 검토 자료로 유지하되, 자동 생성에 매번 새 소재로 제시하지 않습니다.
4. **로컬 검토**: 이미 알려준 정보를 다시 묻는지, 실제 사건·사용자 동의를 꾸며내는지, 같은 결론을 바꾸어 말하는지, 화제가 근거 없이 튀는지, 사용자가 요청하지 않은 상상만 연속 확장하는지를 독립된 참·거짓 항목으로 검사합니다. 이 값은 모델의 판정이며 검증된 확률값이 아닙니다.
5. **출력과 저장**: 검사를 통과한 `speech`만 채팅과 음성에 전달하고 방송 상태를 저장합니다. 내부 판단이나 자동 진행 지시문은 대사로 출력하지 않습니다.

생각의 상태는 진행 중(`open`), 완료(`complete`), 사용자 응답 대기(`awaiting_user`)로 구분합니다. 완료된 생각의 다음 계획은 비우고 다른 화제로 넘어갈 수 있도록 합니다. 새 화면에 대한 반응과 이미 끝낸 화제의 전환을 과거 주제 이탈이라는 이유로 다시 막지 않습니다. 사용자가 답하지 않은 질문을 표현만 바꾸어 재질문하는 경우와 최신 정정을 무시하는 경우도 검사합니다.

판단 단계에도 실제 캐릭터 설정을 전달합니다. 생성 입력에서 제외한 과거 자동 독백은 이미 말한 요점으로 별도 전달하여, 반복을 피하는 과정에서 기억까지 빠지지 않도록 합니다. 생각이 끝났거나 반복으로 거절된 경우에는 이미 해설한 화면을 새 사건으로 다시 제시하지 않고 다른 관심사에서 소재를 선택합니다. 새 화면 관찰이 들어오면 이 전환보다 관찰을 우선합니다. 단어를 금지하거나 일정 횟수마다 무조건 화제를 바꾸는 처리는 아닙니다.

반복 또는 오류가 감지되면 폐기된 초안과 수정 사유를 참고하여 소재부터 다시 구성합니다. 폐기된 초안과 비슷하다는 이유만으로 수정 후보를 탈락시키지는 않으며, 실제로 방송한 대사와 비교합니다. 내용 없이 다음 발언만 예고하는 후보도 재생성 대상입니다. 검토 모델의 새 내용 요약이 비었다는 사실만으로 정상 발언을 반복으로 처리하지 않습니다. 특정 단어나 주제를 금지하거나, 실패 시 준비된 멘트를 대신 읽는 방식은 사용하지 않습니다. 세 번 모두 실패하면 상태 영역에 오류를 표시합니다. 호출·형식 오류도 정상 대사로 숨기지 않습니다.

기본 설정에서는 판단과 생성 요청이 로컬 Ollama로만 전달되며 별도의 API 이용료가 없습니다. 하드웨어·전력 비용은 발생하고, 모델이나 라이브러리의 최초 다운로드에는 인터넷이 필요할 수 있습니다. `ollama_url`을 원격 주소로 바꾸면 해당 서버로 입력이 전송됩니다.

사용자의 직접 질문은 자동 방송 소재 선택과 구분하여 판단합니다. 과거 계획이나 약속을 되묻는 경우 사용자 수락 원문과 전제의 출처를 먼저 확인합니다. 하나가 혼자 제안한 내용과 사용자가 실제 수락한 내용을 구별하며, 인용한 수락 문장은 사용자 원문에 포함되는지 검사합니다. 모델의 출처 분류 자체는 오판할 수 있습니다.

직접 응답이 근거 없는 사건·합의 또는 질문 무시로 거절되면 실패한 소재 계획을 다시 실행하지 않습니다. 최신 질문과 구체적인 검사 사유를 바탕으로 설명·정정할 답을 새로 생성합니다. 이때 자동 독백처럼 새로운 소재를 추가하도록 강제하지 않습니다. 세 차례 모두 실패한 경우에는 실제 거절 사유를 상태 영역에 표시합니다. 원본 기억을 삭제하거나 정해진 사과문으로 응답을 대체하지 않습니다.

## 시스템 요구 사항

- Windows 10 또는 Windows 11
- Python 설치 환경
- Ollama 설치
- 대화 모델 `gemma4:12b`
- 화면 모델 `qwen2.5vl:3b`
- 마이크 사용 시 정상적으로 연결된 입력 장치
- GPT-SoVITS 음성 사용 시 `v2ProPlus` 설치 환경과 참조 음성 파일

음성 엔진, 실행 환경, 음성 모델, 참조 음성 및 언어 자료는 프로젝트 내부의 다음 폴더에서 관리합니다.

```text
yangai\tts\v2ProPlus
├─ .venv312\       Python 음성 합성 실행 환경
├─ GPT-SoVITS\     음성 엔진 및 사전 학습 모델
├─ 三月七\         현재 사용하는 음성 모델 및 참조 음성
├─ nltk_data\      언어 처리 자료
└─ ffmpeg\         오디오 변환 실행 파일 및 라이브러리
```

`config.json`의 `gpt_sovits_*` 파일 경로는 해당 설정 파일이 있는 폴더를 기준으로 해석합니다. 소스 실행은 `tts/v2ProPlus/...`를 사용하며, `build_hana.ps1`은 EXE용 설정을 `../../tts/v2ProPlus/...`로 변환합니다. 따라서 어느 작업 폴더에서 실행하더라도 같은 프로젝트 내부 자료를 사용하며, EXE를 다시 빌드해도 TTS 자료는 보존됩니다. `dist\Hana`만 따로 옮기면 공유 TTS 경로가 끊어지므로 프로젝트 폴더 구조를 함께 유지해야 합니다.

`tts/`는 Git 제외 대상입니다. 대용량 음성 모델과 실행 환경은 커밋·푸시하지 않으며, 저장소를 새로 내려받은 경우에는 사용 권한이 있는 TTS 자료를 별도로 배치해야 합니다. 현재 Python 가상 환경은 이 PC에 설치된 기본 Python 3.12를 사용하므로 다른 PC로의 단순 복사 실행까지 보장하지 않습니다.

## 최초 설치

### 1. Ollama 설치

Ollama가 설치되어 있지 않은 경우 먼저 Windows용 Ollama를 설치해야 합니다. 현재 PC에서는 다음 실행 파일을 사용합니다.

```text
%LOCALAPPDATA%\Programs\Ollama\ollama.exe
```

하나를 실행할 때 Ollama 서버가 꺼져 있어도 하나가 자동으로 서버를 시작하지만, Ollama 프로그램 자체가 설치되어 있지 않으면 자동으로 설치할 수 없습니다.

### 2. 기본 환경 설치

프로젝트 폴더에서 `setup_hana.bat`을 한 번 실행합니다.

설치 스크립트는 다음 작업을 수행합니다.

- Python 가상 환경 `.venv` 생성
- Piper, 화면 캡처, 마이크, 음성 인식, PyInstaller 패키지 설치
- 한국어 Piper 음성 모델 다운로드
- Piper가 사용할 `espeak-ng-data` 복사
- `gemma4:12b` 대화 모델 확인 및 다운로드
- `qwen2.5vl:3b` 화면 모델 확인 및 다운로드

GPT-SoVITS는 프로젝트 내부의 `tts\v2ProPlus` 실행 환경을 사용합니다. `setup_hana.bat`이 GPT-SoVITS나 음성 모델을 자동 설치하지는 않습니다.

### 3. 실행

설치 후에는 다음 파일을 실행합니다.

```text
start_hana.bat
```

실행 순서는 다음과 같습니다.

1. `start_hana.bat`이 숨김 실행기인 `start_hana.vbs`를 호출합니다.
2. `dist\Hana\Hana.exe`가 있으면 빌드된 GUI를 실행합니다.
3. EXE가 없으면 `run_hana.ps1`을 통해 Python GUI를 실행합니다.
4. 하나가 로컬 Ollama API 연결을 확인합니다.
5. Ollama가 꺼져 있으면 `ollama serve`를 숨김으로 실행합니다.
6. Ollama API가 준비된 뒤 마이크, 화면 관찰, 음성 기능을 시작합니다.

## Ollama 자동 실행 및 종료

하나는 `http://127.0.0.1:11434`의 Ollama API를 확인합니다.

### 시작 시 동작

- Ollama API가 이미 실행 중이면 기존 서버를 그대로 사용합니다.
- API가 응답하지 않으면 시스템에서 `ollama.exe`를 찾습니다.
- `ollama serve`를 별도 콘솔 창 없이 실행합니다.
- 최대 45초 동안 `/api/tags` 응답을 확인합니다.
- API가 준비되면 하나의 방송을 시작합니다.

### 종료 시 동작

- 하나가 직접 시작한 Ollama 프로세스만 종료합니다.
- 하나를 실행하기 전에 이미 실행 중이던 Ollama는 종료하지 않습니다.
- Ollama 실행 파일을 찾지 못하거나 45초 안에 서버가 준비되지 않으면 GUI 상태 영역에 원인을 표시합니다.

첫 방송에서 모델이 GPU 메모리에 올라가는 시간은 Ollama 서버 시작 시간과 별개입니다. 서버가 자동으로 시작되어도 첫 답변은 모델 로딩으로 늦어질 수 있으며, 이후 응답은 일반적으로 더 빨라집니다.

## GUI 사용법

GUI에는 다음 기능이 있습니다.

### 마이크

마이크는 Windows 기본 입력 장치를 연속 스트림으로 열어 사용합니다. 음량 기준으로 발화를 감지하고, 기본 1초의 무음 또는 최대 20초의 녹음 구간 뒤에 `faster-whisper`로 전사합니다. 전사 중에도 입력 스트림은 유지되며 제한된 버퍼에 다음 소리를 받습니다. STT가 지나치게 느리면 버퍼 초과에 따른 일부 누락이 발생할 수 있습니다.

인식한 문장은 `너 · STT`로 표시되고, 키보드 입력과 동일한 사용자 응답 경로를 거칩니다. 즉, 음성 원문을 모델이 직접 듣는 방식이 아니라 **음성 → STT 텍스트 → 기억·화면을 참고한 로컬 판단 → 대사 생성** 순서입니다. 잘못 전사한 단어도 모델에 그대로 전달될 수 있으므로 화면의 전사문을 확인해야 합니다.

기본값인 **헤드폰 모드**에서는 하나가 말하는 중에도 듣습니다. 발화를 감지하면 재생 중인 음성과 대기 문장을 취소하고, 생성 중인 자동 멘트는 사용자 입력보다 우선하여 내보내지 않습니다. 이미 진행 중인 모델 추론이나 음성 합성 HTTP 요청 자체까지 강제 중단하지는 않으므로 다음 답변에 지연이 남을 수 있습니다.

음향 반향 제거(AEC)는 구현되어 있지 않습니다. 스피커를 사용하면 하나의 목소리가 사용자 발화로 재인식될 수 있으므로 GUI의 헤드폰 모드를 해제해야 합니다. 이 경우에는 기존처럼 하나 음성 처리 중 인식을 대기합니다. 상단 입력 상태에는 마이크 준비·발화 감지·STT 변환·오류 및 현재 입력 크기가 표시됩니다. 입력 크기가 계속 0이면 Windows 입력 장치·음소거·권한을 확인하십시오. `mic_threshold`는 소음 환경에 맞게 조정할 수 있습니다.

### 화면 관찰

화면 관찰 설정에서 다음 중 하나를 선택할 수 있습니다.

- 전체 화면
- 열려 있는 특정 창

선택한 창이 종료되면 화면이 검은색으로 고정되지 않습니다. 하나는 선택한 창을 찾을 수 없는 경우 전체 화면 또는 현재 데스크톱 영역을 대체 화면으로 사용합니다.

화면 관찰은 기본적으로 분석을 마친 뒤 5초를 기다리고 다시 수행합니다. 화면 분석 요청의 제한 시간은 기본 30초입니다. 따라서 실제 관찰 주기는 분석 시간에 따라 더 길어질 수 있습니다.

화면 분석 중 사용자의 음성이나 자동 대화 요청이 들어오면 새 화면 분석을 시작하지 않고 대화 처리를 우선합니다.

새 관찰이 하나의 음성 재생 중 들어와도 버리지 않고 다음 발언 차례까지 보존합니다. 첫 화면 관찰을 기다리는 동안에는 화면을 이미 본 것처럼 자동 독백을 시작하지 않습니다. 관찰 실패 또는 화면 기능 해제 시에는 화면 없이 대화를 이어갈 수 있습니다. 상단에는 최근 관찰 문장, 캡처 후 경과 시간 또는 오류가 표시됩니다. `화면 켜짐`은 분석이 성공했다는 뜻이 아닙니다.

화면 자료의 유효 시간은 분석 완료 시간이 아닌 캡처 시각부터 계산합니다. 45초가 지난 이미지와 관찰은 현재 화면으로 사용하지 않습니다. 글자나 장면 분석에는 여전히 오독 가능성이 있으며, 화면 변화는 실제 관찰을 비교해야 판단할 수 있습니다.

사용자가 현재 화면을 명시적으로 질문하면 이전 캐시 대신 선택한 대상을 새로 캡처합니다. 분석이 실패하면 이전 장면을 새로 본 것처럼 사용하지 않습니다. 캡처 대상을 바꾸면 이전 대상으로 생성하던 자동 대사는 취소합니다. 새 관찰은 실제 화면 근거로 대사를 만든 뒤에만 처리 완료로 표시합니다.

### 음성

현재 `config.json`은 GPT-SoVITS를 기본 음성 엔진으로 사용하도록 설정되어 있습니다.

GPT-SoVITS 음성은 다음 순서로 처리됩니다.

1. 모델의 답변 생성과 구조·반복 검사가 끝날 때까지 기다립니다.
2. 검사를 통과한 답변 전체를 한 번의 GPT-SoVITS 요청으로 보냅니다.
3. 생성된 WAV의 음량과 좌우 음량 비율을 조절합니다.
4. 답변 전체를 하나의 파일로 Windows 기본 오디오 장치에서 재생합니다.

이전에는 앞 문장의 재생이 끝난 다음 문장을 합성하여 문장 사이에 합성 대기 시간이 발생했습니다. 현재는 답변 안의 문장 사이에 새 합성을 기다리지 않습니다. GPT-SoVITS가 내부적으로 텍스트를 분할하는 과정은 남아 있으며, 조각 사이에 추가하는 간격은 기본 0.12초입니다. 음성 자체에 포함된 숨·쉼까지 모두 0.12초가 되는 것은 아닙니다.

첫 토큰부터 즉시 음성을 내는 방식은 아닙니다. 한 답변의 WAV가 완성될 때까지 기다리므로 대화 생성·검사·음성 합성 시간이 합산됩니다. 문장 사이의 긴 공백을 없애는 대신 첫 문장도 전체 합성이 끝난 뒤 들립니다. 서로 다른 답변 사이의 기본 3초 대기와 다음 답변 생성 시간은 별개이며 변경하지 않았습니다. 글의 의미상 연결과 화제 전개 품질도 이 음성 처리만으로 해결되지 않습니다.

#### 항상 가까운 마이크와 좌우 이동

하나는 항상 마이크 바로 가까이에서 말합니다. 대화 모델은 실제 대사와 함께 `voice.tone`, `voice.position`을 선택하며, 사용자 요청이 없더라도 상황과 감정에 맞춰 말투와 좌우 위치를 고를 수 있습니다. 정해진 주기나 무작위로 연출을 바꾸지 않습니다. 기본은 가까운 중앙 음성입니다. 연출 정보는 화면 대사나 TTS 입력 문장에 넣지 않고 음성 처리에만 전달합니다.

말투는 보통·밝음·진지함·부드러움·화남·놀람·두려움 중 하나입니다. `soft`는 음량과 속도를 낮춘 보통 발성입니다. 속삭임 변환·선택 지시·강도 설정은 제거했습니다. 과거 데이터의 `whisper` 값이나 알 수 없는 말투는 `neutral`로 처리하며, 이전 `voice_whisper_strength` 설정은 사용하지 않습니다. 위치는 마이크 가까운 중앙·왼쪽·오른쪽으로 제한합니다. `close` 계열은 가까운 상태에서의 좌우 정도를 나타내며, 과거 데이터의 `far` 값은 중앙으로 처리합니다. 마이크 음성 인식에 쓰는 `faster-whisper`는 별도 기능으로 그대로 유지합니다.

- 말투에 따라 합성 속도와 음량을 제한된 범위에서 바꿉니다. 울리거나 겹쳐 들리는 음색을 피하기 위해 합성 후 높낮이를 바꾸던 Rubber Band 처리를 제거했습니다. 높낮이는 이제 합성 모델과 참조 음성의 원래 억양에 따르며, 별도로 강제 변조하지 않습니다.
- 현재 참조 음성 폴더에 화남·놀람·두려움으로 표시된 녹음이 있으면 해당 말투에서 사용합니다. 없으면 설정된 기본 참조 음성을 사용합니다. 원본 참조 파일은 수정하지 않습니다.
- 이전 버전의 19/26밀리초 반사음·거리 감쇠뿐 아니라 남아 있던 귀 사이 시간차 처리도 제거했습니다. 에코·리버브·방 울림·멀리서 부르는 효과를 추가하지 않습니다. 생성 음성을 음량 조절과 시작·끝 5밀리초 페이드만 거쳐 출력하며, 원음에 이미 포함된 울림을 제거하는 기능은 아닙니다.
- 헤드폰용 좌우 감각은 동일한 시점의 원음을 양쪽 귀에 서로 다른 음량으로 전달하여 만듭니다. 어느 위치에서도 지연이나 위상 가공을 하지 않습니다. 위치가 바뀌면 약 0.8초 동안 좌우 음량 비율이 부드럽게 변하며, 음원이 마이크에서 멀어지지 않습니다.
- 측정된 HRTF를 사용하는 완전한 3D 음향은 아닙니다. 앞뒤·높이 구분이나 머리 회전 추적은 지원하지 않습니다. 음색 변형을 줄이기 위한 단순한 좌우 음량 조절입니다.
- 하나의 답변에는 하나의 연출을 적용합니다. 문장별로 서로 다른 감정 연기를 정밀하게 지시하는 기능은 없습니다. 합성 모델 자체의 억양과 발음 품질에도 영향을 받습니다.
- 효과 처리에 실패하면 원래 합성 음성으로 재생하고 상태 메시지를 남깁니다. 효과 오류만으로 음성 출력을 끄지 않습니다.

GUI 하단의 `감정 말투`, `근접 좌우 음성 · 헤드폰용`을 개별적으로 켜거나 끌 수 있습니다. 전자를 끄면 기본 참조 음성과 속도·음량을 사용합니다. 후자를 끄면 좌우 위치가 중앙으로 고정됩니다. 변경은 다음 음성부터 적용되며 두 기능을 모두 끄면 생성 WAV의 후처리를 생략합니다. 세부 강도는 실행 위치의 `config.json`에서 조절합니다.

| 설정 | 기본값 | 의미 |
|---|---:|---|
| `voice_expression_enabled` | `true` | 말투별 참조 음성·속도·음량 사용 여부 |
| `voice_expression_strength` | `1.0` | 속도·음량 변화 강도, 0~1. 참조 음성 선택은 별개입니다. |
| `voice_spatial_enabled` | `true` | 근접 헤드폰용 좌우 효과 사용 여부 |
| `voice_spatial_strength` | `0.8` | 좌우 차이 강도, 0~1. 어느 값에서도 반사음을 추가하지 않습니다. |
| `tts_fragment_interval` | `0.12` | GPT-SoVITS 내부 음성 조각 사이에 추가하는 간격(초), 0~0.5 |

구현에서 사용하는 합성 인자는 [GPT-SoVITS API](https://github.com/RVC-Boss/GPT-SoVITS/blob/main/api_v2.py)를 참고할 수 있습니다. 음성 후처리에는 FFmpeg의 피치·HRTF 필터를 사용하지 않습니다. GPT-SoVITS 서버 내부에서 필요한 FFmpeg 경로 설정은 유지합니다.

GPT-SoVITS를 사용할 수 없을 때에는 `config.json`에서 다음과 같이 Piper로 전환할 수 있습니다.

```json
{
  "tts_engine": "piper"
}
```

### 자동 방송 멘트

하나는 사용자의 입력이 없어도 자동 발언을 요청합니다. 화면 관찰이 실패하거나 비활성화되어 있어도 이전 대화와 캐릭터의 관심사를 바탕으로 이어갈 수 있습니다. 화면이 없을 때에는 현재 화면을 본 것처럼 말하지 않도록 지시합니다.

하나의 답변과 음성 재생이 끝난 뒤 기본적으로 3초를 기다리고 다음 생성 요청을 시작합니다. 3초 안에 다음 음성이 재생된다는 뜻은 아닙니다. 자동 발언 생성 도중 사용자가 말하면, 완료된 자동 발언을 내보내지 않고 대기 중인 사용자 발화에 대응합니다.

## 캐릭터 설정

캐릭터의 핵심 설정은 다음 파일에서 관리합니다.

```text
hana_prompt.txt
```

현재 하나는 다음과 같은 설정을 사용합니다.

- 대한민국의 언어, 문화, 계절, 사람들의 기억에서 태어난 가상의 신령
- 인간이 아니라 인간 세상에 머물기 위해 인간의 모습과 목소리를 선택한 존재
- 게임과 방송을 좋아하는 버튜버
- 화면에 보이는 사실과 자신의 감정·판단을 구분하는 방송인
- 사용자와 시청자를 고객이나 상사가 아닌 방송 동료로 대하는 관계
- 장난스럽고 살짝 도도하지만 가까운 사람에게는 다정한 성격
- 정해진 답변 목록 대신 대화 모델로 대사를 생성하는 가상의 방송 인격

캐릭터의 말투, 과거, 감정, 게임 취향, 방송 행동을 수정하려면 `hana_prompt.txt`를 수정합니다. 이는 매 요청에 전달하는 설정이며, 모델의 가중치를 재학습한 것은 아닙니다. EXE로 실행하는 경우에는 `dist\Hana\hana_prompt.txt`가 사용됩니다.

## 기억과 세션 저장

하나의 기억은 프로그램 실행 위치의 `data` 폴더에 저장됩니다. EXE로 실행하는 경우 기본 위치는 다음과 같습니다.

```text
dist\Hana\data
```

### 방송 세션

방송을 시작할 때마다 다음 형식의 새 파일이 생성됩니다.

```text
data\sessions\session_YYYYMMDD_HHMMSS_프로세스번호.jsonl
```

현재 방송 세션의 사용자 발화와 하나의 답변은 이 파일에 순서대로 저장됩니다.

### 장기 기억

장기 기억은 다음 파일에 저장됩니다.

```text
data\memory.json
```

기억에는 다음 정보가 포함될 수 있습니다.

- 사용자가 직접 말한 사실과 선호
- 사용자와 하나의 관계 상태
- 하나의 현재 감정
- 이어지고 있는 주제
- 최근 대화 일부
- 마지막으로 관찰한 화면 흐름
- 이전 방송에서 생성된 요약
- `broadcast_state`: 현재 화제, 입장, 감정, 다음에 이어갈 거리, 생각의 완료 상태
- `user_quotes`: 사용자가 실제로 말한 호칭·선호·사실의 인용문
- `user_statements`: 모델의 인용 추출과 별개로 보관하는 최근 사용자 발화 원문 최대 30개입니다. 질문·가정은 사실로 간주하지 않으며, 최근 대화에 이미 포함된 문장은 중복 전달하지 않습니다.
- `spoken_points`: 이미 방송한 대사의 앞부분을 최대 32개 보관하는 반복 비교 자료입니다. 사용자 사실이나 다음에 실행할 계획으로 취급하지 않으며, 최근 대화에 이미 있는 부분은 중복 전달하지 않습니다.

수락된 답변마다 현재 상태와 최근 대화를 저장하며, 사용자 발화가 8회 누적될 때마다 별도의 기억 요약을 요청합니다. 사용자 인용문은 모델이 골라도 현재 사용자 발화에 실제로 포함된 문자열만 저장합니다. 자동 발언이 사용자 사실로 등록되는 것을 막기 위한 구분입니다. 인용문은 최근 30개까지 유지하며 완전한 영구 회상을 보장하지 않습니다.

자동 발언이 많이 쌓여도 최근 사용자 대화가 기록 창에서 즉시 밀려나지 않도록 일부 자리를 확보합니다. 과거 버전의 출처 없는 자동 독백은 반복 오염을 줄이기 위해 다음 프롬프트에서 제외하지만 원본 세션 파일은 삭제하지 않습니다. 이전 화면 메모는 재실행 직후의 실제 화면으로 취급하지 않습니다.

기억 파일의 저장과 모델의 정확한 회상은 별개입니다. 저장된 정보를 모델이 잘못 해석하거나 놓칠 수 있으며, 오래된 요약에도 오류가 있을 수 있습니다. 생성 후보와 재생성 사유는 로컬 `data\generation.jsonl`에 기록합니다. 이 파일과 세션 기록에는 대화 내용이 포함될 수 있으므로 공개 저장소에 올리지 않도록 제외되어 있습니다.

소스 코드에서 EXE를 다시 만들려면 프로젝트 폴더에서 다음 명령을 실행합니다.

```powershell
.\build_hana.ps1
```

빌드 결과는 다음 위치에 생성됩니다.

```text
dist\Hana\Hana.exe
```

빌드 스크립트는 임시 빌드 폴더를 사용하며, 기존 `dist\Hana\data` 폴더는 백업한 뒤 새 빌드 결과에 복원합니다. 따라서 세션 기록과 장기 기억은 빌드 과정에서 유지됩니다.

## 문제 해결

### “Ollama 자동 시작 실패”가 표시되는 경우

다음 항목을 순서대로 확인합니다.

1. Ollama가 설치되어 있는지 확인합니다.
2. `%LOCALAPPDATA%\Programs\Ollama\ollama.exe`가 존재하는지 확인합니다.
3. `config.json`의 `ollama_url`이 `http://127.0.0.1:11434`인지 확인합니다.
4. `setup_hana.bat`을 실행하여 필요한 모델이 설치되어 있는지 확인합니다.
5. 다른 프로그램이 11434 포트를 사용하고 있지 않은지 확인합니다.

### 모델이 없다는 오류가 표시되는 경우

다음 명령으로 설치된 모델을 확인합니다.

```powershell
ollama list
```

필요한 모델이 없다면 `setup_hana.bat`을 다시 실행하거나 다음 명령을 직접 실행합니다.

```powershell
ollama pull gemma4:12b
ollama pull qwen2.5vl:3b
```

### 음성이 나오지 않는 경우

- `config.json`에서 `tts_enabled`가 `true`인지 확인합니다.
- GPT-SoVITS 경로와 참조 음성 파일 경로가 실제로 존재하는지 확인합니다.
- GPT-SoVITS를 사용할 수 없다면 `tts_engine`을 `piper`로 변경합니다.
- `data\tts_playback.log`와 `data\gpt_sovits.log`에서 음성 생성 및 재생 오류를 확인합니다.

### 화면을 제대로 읽지 못하는 경우

- 화면 관찰이 켜져 있는지 확인합니다.
- `qwen2.5vl:3b` 모델이 설치되어 있는지 확인합니다.
- 전체 화면 모드와 특정 창 모드를 바꾸어 확인합니다.
- 화면 모델은 작은 글자나 복잡한 화면을 항상 정확하게 읽지는 못합니다.
- 화면 분석 요청의 제한 시간은 기본 30초입니다. 최신 관찰이 45초 이상 갱신되지 않으면 현재 화면 자료에서 제외합니다.

## 제한 사항

- 하나는 화면 밖의 정보를 직접 볼 수 없습니다. 사용자가 말했거나 실제 화면에서 확인된 내용만 근거로 사용합니다.
- 첫 실행이나 모델이 메모리에서 내려간 직후에는 모델 로딩으로 응답이 늦어질 수 있습니다.
- 화면 분석과 음성 합성은 사용하는 GPU, CPU, 메모리, 디스크 속도에 따라 처리 시간이 달라집니다.
- GPT-SoVITS 참조 음성의 품질과 참조 문장에 따라 하나의 음성 품질과 감정 표현이 달라질 수 있습니다.
- 기억 파일을 삭제하거나 `memory.json`을 직접 수정하면 하나의 장기 기억과 관계 흐름이 변경됩니다.
- 로컬 모델의 한국어 표현, 사실 정확도, 자발적인 화제 전개에는 한계가 있습니다. 반복 검사도 의미상 같은 발언을 놓칠 수 있습니다.
- `emotion`은 캐릭터 반응을 이어가기 위한 상태 값입니다. 실제 감정이나 의식이 존재한다는 의미는 아닙니다.
- 응답 시간은 1초 이내로 보장하지 않습니다. 화면 모델 및 음성 모델과 GPU 메모리를 공유하면 추가 지연이 발생할 수 있습니다.

## 검증

마이크·화면 캡처·음성 출력을 실행하지 않고 대화 처리 회귀 검사를 수행할 수 있습니다.

```powershell
.\.venv\Scripts\python.exe test_hana.py --headless
.\.venv\Scripts\python.exe test_inputs.py
.\.venv\Scripts\python.exe test_grounding.py
.\.venv\Scripts\python.exe test_grounding.py --live
.\.venv\Scripts\python.exe test_grounding.py --live --built --output grounding-built.json
.\.venv\Scripts\python.exe test_voice.py
.\.venv\Scripts\python.exe test_voice.py --live
.\.venv\Scripts\python.exe test_voice.py --live-model
.\.venv\Scripts\python.exe test_inputs.py --live
.\.venv\Scripts\python.exe test_dialogue_quality.py --live
.\.venv\Scripts\python.exe test_hana.py --live gemma4:12b --output data/diagnostics/conversation.json
```

`test_hana.py`는 구조 출력·기억·기존 GUI 경로를 검사합니다. `test_inputs.py`는 연속 입력·TTS 중 인식·음성 취소·화면 반응 보존을 모의 장치로 검사합니다. `test_inputs.py --live`는 Piper로 만든 시험용 한국어 음성을 실제 STT에 넣고 GUI 사용자 경로와 실제 로컬 판단·대사 생성을 실행합니다. 이어서 시험용 강의 이미지를 실제 화면 모델로 읽고, 이전의 상상 독백에서 현재 관찰로 돌아오는지 네 차례 시험합니다. 사용자 마이크를 녹음하거나 실제 데스크톱을 캡처하지 않고, 시험용 음성은 임시 폴더에서 처리 후 삭제합니다.

`test_dialogue_quality.py --live`는 고정된 판단 사례와 자동 발언을 검사합니다. `test_hana.py --live`는 16차례 연속 대화를 기록합니다. 이 시험들은 개인 기억을 사용하지 않으며 실제 마이크·게임·음성이 동시에 동작하는 장시간 방송 품질을 보증하지 않습니다.

`test_grounding.py`는 사용자 원문과 하나의 제안 분리, 직접 질문의 재생성 경로, 실제 실패 사유 표시를 검사합니다. `--live`는 별도 로컬 서버에서 사용자 수락이 없는 제안과 수락이 있는 약속을 대조합니다. 선택적으로 `--memory dist/Hana/data/memory.json`을 지정하면 해당 기억을 읽기 전용으로 재현합니다. 이 경우 시험 결과에 개인 대화가 포함될 수 있으며 결과는 Git 제외 경로인 `data/diagnostics/`에만 저장됩니다. 기억 원본은 변경하지 않습니다. 대사 반환과 출처 분류를 자동 검사하며 표현의 자연스러움은 별도 검토가 필요합니다.
